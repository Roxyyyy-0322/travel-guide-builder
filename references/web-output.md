# 网页交付

优先轻量静态站点，既有项目沿用合适框架。不要无故加入账户、数据库或复杂后端。共用结构化数据，避免多处手写事实。

入口：总览、按日行程、路线地图、票券预约、购物、新手手册、预算、来源/更新。用分页或标签而非超长首页，支持深链接、刷新与手机返回。移动端/桌面可读，关键操作不只依靠悬停。日程卡片含交通、预约、费用和餐食；不要为美观隐藏细节。

预算交互中已确认项锁定，估算可编辑；本地勾选不能伪称同行同步。公开稿本身不含私密原始记录。

## 地图

- 每日点位和路线区分步行/地铁铁路/公交，用颜色＋线型＋文字图例。点击点位有站名/步骤/用时/费用。
- 核对坐标对应实际入口。同城站点连线标“交通示意线，非实际轨道”；直线不能当步行导航，真实路线需合法路由服务。
- 使用目标地区可访问、许可允许的底图，保留署名。密钥走配置；前端只放允许公开并限域的令牌，秘密密钥不入包。
- 视野/缩放合理；隐藏标签切换后重新计算地图尺寸，避免初始容器宽高0。
- 部分加载诊断顺序：容器尺寸→resize/invalidateSize→点位范围→网络/CORS/429→授权/区域可用性。用户联网不代表瓦片服务正常。
- 实看地图街道与地名；HTTP200、图片加载完成、naturalWidth非0都不证明正常，可能返回错误告示图片。
- 超时有明确提示、重试与经验证备用；文字路线/导航链接始终可用。不能无限重试、绕封禁或使用非法代理。
- 在线地图不能承诺离线；离线需求给许可允许的静态示意图与文本。

## 分享与更新

先区分公开持链接、登录限制、本地文件。公开链接可被转发，禁止放订单票码。用户要“聊天改、同一地址看新版”不等于要多人编辑系统。

每版有更新时间和变更说明。发布同步代码与数据并处理缓存；不能只刷新JSON留旧JS。核验新打开和旧标签刷新都看到同一版本。

用户要求发布且有可用工具/权限才部署，优先指定站点。不要要求用户把密码/token发到聊天。登录墙、本地服务器、仅本地生成都不是公开上线。平台受阻先诊断，已授权迁移才更换；没有能力则交付站点包并明确未部署。

发布只含审查过的站点目录，排除.env、会话、日志、订单和私密数据。匿名验证公开URL、版本、深链接刷新、地图、手机视图。最终给真实网址（若已上线）、可移植站点包和必要启动步骤；需要HTTP服务时不承诺双击HTML必定可用。
