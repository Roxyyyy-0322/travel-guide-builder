# 需求与调研

优先复用会话。最小输入：目的地、含年份的日期、偏好；再选网页/PDF。未定航班住宿时用建议区域和首末日缓冲，不虚构已购项目。

| 类别 | 决定性信息 | 未知时处理 |
|---|---|---|
| 时间 | 年份、抵离、当地时区、航站楼、跨日 | 日期歧义先问；未知航班留缓冲 |
| 人员 | 人数、儿童年龄段、体力/无障碍需求 | 不推断国籍、年龄、身体状况 |
| 入境 | 国籍/出发地/证件类型是否影响要求 | 只给核验路径，不断言免签 |
| 预算 | 总额/每人、币种、是否含机酒购物 | 明确口径，分固定和增量 |
| 偏好 | 必去/不去、兴趣、节奏、日间起止 | 采用明确假设，不硬塞景点 |
| 已购 | 酒店区域、票券准确版本/有效期、预约 | 只要权益描述，不要订单码 |
| 输出 | 网页/PDF/都要、公开方式、脱敏选择 | 公开前先审查隐私 |

手机号、手机型号、银行卡名称只在确实影响操作且用户愿提供时询问。普适版教用户检查SIM/eSIM支持、境外支付开关，不收集号码、证件或卡片照片。

## 来源顺序

1. 政府出入境/海关、机场、交通运营商、景点官网、商场、票券发行方。
2. 先查固定约束：抵离、休馆、指定时段、发售时间、季节交通、假期和日落。
3. 按地理区域排日程，计入步行、候车、站内换乘和排队。
4. 核实门票和交通成本，最后加入餐食、购物与天气备选。
5. 每项来源记录标题、原页URL、核验日期、旅行适用日期、支持字段和不确定性。

当前价格、班次、营业和政策必须联网核实。官方未公布旅行日期班表时，用当前参考频率并提供复核入口；不假造精确发车时间。无法联网只能给标注待核实的草案。不要将搜索摘要或地图评论当完整官方规则。

冲突资料比较发布日期、商品版本和适用范围。用户已在自己的券内确认权益时，记为用户确认，不重复要求证明；继续核查流程、预约和限制。用户确认不代表同类商品通用。

## 状态

- 官方确认：页面直接支持，有核验日期。
- 用户确认：会话中的已购权益或预约，限本旅客。
- 估算：门到门时间、排队、餐饮、换汇，说明浮动与条件。
- 待核实：未来班表、未公布活动等，给复核入口和影响。
